# Particle Filter benchmarks

A reproducible way to measure what Particle Filter costs and what it saves: overhead when installed but
inactive, the effect of global and zone filtering, how both scale with particle load, rule and zone count,
and how it compares with other particle-control mods doing the same job.

> **Status: groundwork only. No performance results exist yet.** This directory has the plan, the
> analysis tools, a pilot that checked the measurement pipeline on a frame-capped title screen, and the
> synthetic harness (NeoForge 1.21.1), which so far has only passed functional checks. Don't
> quote anything here as a Particle Filter performance figure. Performance runs are **blocked** until the
> owner confirms the laptop's power-limit problems are fixed. Start with [HANDOFF.md](HANDOFF.md).

The benchmark code and documents were written by Claude (AI), like the mod itself. The owner reviews the
design and decides which campaigns run.

## Tools

| Script | Purpose |
|---|---|
| `tools/frametimes.py summarize LOG [--skip-seconds S] [--duration-seconds D] [--cap-fps N] [--json OUT]` | Metrics and sanity checks for one MangoHud CSV or harness frame log (`.gz` works too) |
| `tools/compare.py CAMPAIGN --reference B [--margin-pct 1]` | Paired comparison of configurations with bootstrap intervals and verdicts; lists every run and every exclusion |
| `tools/schedule.py --configs A B C D --blocks 8 --seed N` | Counterbalanced (Williams design) run order |
| `tools/collect_env.py --out env.json [--instance DIR] [--java PATH] [--pid PID]` | Hardware, software, display, power and mod-list snapshot (read-only; home paths and serials left out) |
| `tools/sample_system.py --pid PID --out-dir DIR` | Per-thread CPU (and which core), clocks, temperature, RSS, `nvidia-smi` GPU stats during a run. Don't use `--self-cpu`: the owner prohibits changing CPU affinity |
| `tools/make_pf_config.py synthetic\|miss\|rules\|zones` | Particle Filter configs for the benchmark configurations |
| `tools/pilot_devclient.sh OUT [WARMUP] [DURATION] [--hide]` | Pipeline pilot: dev client under MangoHud on the title screen |
| `harness/pfbench.py template\|run\|check` | Synthetic harness launcher: template world, one launch per configuration set, functional checks ([harness/README.md](harness/README.md)) |

Tests: `python3 -m unittest discover -s benchmarks/tools/tests -v` (run from the repository root).

## Data layout

```
results/<campaign>/
  PILOT.md or report.md          what was done and what it shows
  runs/<run-id>/
    run.json                     metadata (templates/run.json); compare.py reads config, block, workload, exclude
    summary.json                 frametimes.py output (metrics, checks, usable)
    env-before.json, env-after.json
    mangohud/*.csv               raw frame logs (never edited)
    system/{threads,system,gpu}.csv
```

Raw data is never edited or deleted. Bad runs are marked `"exclude": true` with a reason in `run.json`
and stay in place. Large campaigns should gzip their CSVs (the tools read `.gz`). Logs such as
`gradle.log` contain local paths: review them before publishing a campaign.

## What this suite will not do

- Change Particle Filter's production code, a Minecraft installation, or a world. Benchmarks run in the
  repo's dev client or in copies.
- Publish claims before a campaign is complete and reviewed. Equivalent, inconclusive and negative results
  are reported the same way as positive ones.
